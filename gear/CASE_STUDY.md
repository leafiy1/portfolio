# GearPick 项目案例复盘（数据策略代表作）

> 内部文档：可直接用于复盘讲稿与复盘，标注【待补充】处请用真实数据替换。
> 作者：陈昊｜更新：2026-08-19（v7.1 核价/配图与误配清洗）

---

## 一、背景

GearPick 最初是一版"能用但粗糙"的单页推荐工具：60 款产品 + 简单表单 + 规则推荐，
早期反馈为**"粗糙、内容少"**。复盘其问题，本质不是"页面不够花"，而是：

1. **数据薄**：产品只有 8~12 个字段，说不清"为什么是它"；
2. **不可解释**：推荐结果只有一句"推荐理由"，用户无法验证、无法溯源；
3. **链路断**：推荐完就结束了，没有"理解 → 对比 → 带走结果"的后续动作；
4. **无兜底**：空结果、加载失败等状态没有设计；
5. **没有方法论背书**：既不像产品、也不像数据作品，缺少可讲的"决策故事"。

**v1→v2** 完成了「数据做厚 + 可解释链路 + 数据治理流程」；**v2→v3** 聚焦
**门面（视觉提质）** 与 **可信（数据核对/内容深化）**；**v3→v4** 聚焦
**数据扩库** 与 **缺价治理**：把 168 款近两年新品按同一套信源和留空规则并入产品库；
**v4→v4.1** 完成 42 款缺价型号的公开价格核实，并把价格来源与核实日期写进数据；
**v4.1→v4.2** 基于只读审计修复推荐文案异常、补齐鼠标垫通用字段，并统一文档口径；
**v4.2→v4.3（本轮）** 联网补齐 11 款公开参考价，仅保留 Wooting Two HE 待核实。
产品主页的每一个子项目都值得被当成"会被使用者仔细看"的门面来打磨。

## 二、产品职责

- **产品经理**：定义问题、设计推荐链路、决定"做什么/不做什么"；
- **数据策略**：设计信源体系与数据治理规则、数据厚化字段、评分规则、数据核对闭环；
- **前端落地**：信息架构、可解释 UI、状态设计、响应式、视觉系统（推荐人/数据档案馆）；
- **交付物**：`index.html`（工具）、`products.json`（数据）、`README.md`（口径）、`CASE_STUDY.md`（本复盘）。

## 三、核心决策

### 决策 1：为什么用"透明规则推荐"而不是"算法黑盒"

| 维度 | 算法黑盒 | 透明规则推荐（本方案） |
| --- | --- | --- |
| 可解释性 | 分数不可解释，用户只能信 | 每一步规则公开，逐条可溯源 |
| 数据门槛 | 需要大量行为/评分数据 | 3070 款产品 + 信源即可启动 |
| 信任建立 | 黑盒难建立信任 | 信源覆盖度透明，诚实展示短板 |
| 差异化 | 与大厂电商推荐同质 | "推荐 + 溯源"是内容型产品的护城河 |
| 适合场景 | 有海量数据时 | 垂直小众、数据有限、决策低频高价值 |

**结论**：外设推荐是"低频、高客单、强信任"决策，用户要的不是"更高的分"，
而是"为什么推荐它、凭什么是它"。透明规则推荐用可解释性换信任，用小数据启动换可行性。

### 决策 2：为什么"三重信源交叉验证"

单一信源都有偏差：职业选手配置**权威但滞后**（职业选手可能用赞助商产品）；
UP主横评**时效好但有商单嫌疑**；社区口碑**真实但有噪音**。因此：

- `fireopen 职业选手配置` → 验证"顶级玩家真的在用"（权威背书）；
- `B站 UP 主横评` → 验证"当下价格与购买建议"（时效）；
- `社区口碑（NGA / Reddit / 什么值得买）` → 验证"长期使用后的真实体验"（长尾校验）。

三条信源相互交叉，重合度高的产品优先推荐；覆盖不足的产品如实标注"单信源（待补强）"。

### 决策 3：数据治理红线（宁缺毋滥）

- 严禁虚构真实产品的规格参数，无法核实的字段**留空**（前端显示「—」，README 记录缺失）；
- 新增型号必须带 `sources` 字段，否则不入库；
- **核对只改可核实参数**：v3.0 逐条比对公开信源后，修正 5 处参数（详见第五节），
  并把「无法在本环境二次核实的条目继续留在清单、绝不写入数据」写进流程。

> 这一决策本身是可讲的：**产品经理要为数据质量负责，宁可库小，不可库假。**

### 决策 4（v3 新增）：为什么把视觉做成"推荐人 / 数据档案馆"

产品主页工具页被评价"粗糙"，本质不是少几个动画，而是**没有视觉主张**。v3 定下方向：

- **暖中性纸感底色 + 墨色文字 + 陶土橙单一强调色**：专业但不冰冷，与产品主页暖色系一致；
- **Hero 首屏放真实数据可视化**（收录数 / 信源覆盖结构 / 三类信源条形图，全部由 products.json 实时计算）：
  把"我有什么数据、数据有多可信"直接摆到门面，而不是一句空泛 slogan；
- **档案化签名细节**：编号铭牌 №01、切角档案角标、计分规则 Mono 脚注、页脚数据治理红线——
  每一个细节都在重复同一个主张：**这是一份可追溯的数据档案，不是一个花哨的 demo**。

## 四、改造落地

### v1 → v2（数据做厚 + 可解释）

1. **数据做厚（v1 → v2）**：每款产品新增 7 个维度——`budget_tier` 预算档位、`suitable_games` 适合游戏、
   `recommend_reason` 推荐理由、`notes` 注意事项、`sources` 结构化信源、`verification_status` 信源覆盖状态、
   `price_note` 价格口径。型号均真实在售；经独立验收与公开信源逐项核对后，**修正 3 处硬参数错误**
   （炼狱蝰蛇V4 Pro 重量/传感器、雷柏VE3 连接/单元、漫步者G6 Pro 连接/价格）。
2. **体验升级**：完整链路（选品类 → 填需求 → 推荐 → 为什么推荐它 → 对比 → 复制/导出）；
   空结果自动放宽、加载态、错误态；桌面/移动端响应式。
3. **可解释区**：得分构成（需求匹配/信源/偏好加分）+ 推荐理由 + 注意事项 + 信源覆盖圆点与逐条链接。
4. **独立验收**：无改造记忆的独立评审执行全链路测试（42 项断言全过）+ 数据与公开信源比对，P0 零项。

### v2 → v3（视觉提质 + 数据核对 + 内容深化）

1. **视觉重构**：按「推荐人/数据档案馆」美学方向重做整页——暖纸色板、Serif/Sans/Mono 三层字体阶梯、
   正文 16px、统一圆角/阴影/焦点环；Hero 首屏加入真实数据可视化（66 款收录、三重 10 / 双源 26 / 单源 30 结构图、
   三类信源覆盖条形图）；结果卡、对比弹窗、导出、状态空态全部统一视觉语言。
2. **数据核对闭环**：逐条核对 README「数据待核对清单」，**修正 5 处参数**（mp-001 双子星价格/尺寸、
   mp-002 飓鸦幻价格/尺寸、m-029 唯卓 Cloud 价格/重量、kb-005 飞智FS68 触发行程、m-021 龙鳞2ACE 模具/握法），
   全部有公开信源可查；其中 4 款补充信源后由「单信源」升级为「双信源交叉验证」（覆盖变为 三重 10 / 双源 26 / 单源 30）。

## 六、复盘

**做得好的**：

1. 把"数据质量"变成了产品主张——诚实展示信源覆盖度，反而比假装全知更可信；
2. 可解释性不是加一个弹窗，而是贯穿评分、展示、导出的完整叙事；
3. 数据厚化脚本可复跑、可幂等，说明"这是工程化数据流程，不是一次性手工"；
4. v3 把"产品主页门面"当成一等公民：视觉主张（推荐人/数据档案馆）与数据主张（可溯源/不虚构）
   互为表里——**好看的档案感，恰好也是"可信"的视觉隐喻**。

**不足与下一步**：

1. 57 款国产型号社区口碑信源未采集 → 建立 NGA/贴吧口碑采样表（【待补充】）；
2. 评分权重靠人工设定 → 埋点采集"购买/不购买"反馈，用真实数据校准；
3. 价格是静态参考价 → 接电商比价 API 做实时价格；
4. 无线鼠标续航、键盘回报率、耳机频响/阻抗等可选字段待批量补录（需逐条核实，不猜测）；
5. 剩余 1 款缺价型号（kb-029 Wooting Two HE）是当前最明确的价格核对清单；
6. 品类已扩至 7 个 → 下一步对新品类逐条核价、补参数与真实使用日志。

**一句话总结**：这个项目证明的不只是"我会做推荐工具"，而是——
**我知道在数据有限时怎么用可解释、可溯源、诚实的数据策略建立信任，并且能把产品、数据、前端三个角色串起来落地。**
v3 又补上了最后一块拼图：**当产品主页本身被当作"产品"来设计时，我交付的是一份有主张、可验证、经得起细看的门面。**
