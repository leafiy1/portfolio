# 迷宫饭 v2.5.0 试玩招募包

> 用途：招募 5 位真实玩家，完成「从零开始打一场战斗 + 做一顿料理回血」的统一任务。
> 状态：2026-08-19 用户确认迷宫饭不需要真人试玩，本招募包不再执行；验收以 `verify_game.cjs` 自动化回归为准。

## 1. 招募文案（可直接复制）

帮我试玩一个网页游戏《迷宫饭 · 冒险食堂手记》，大概 5-10 分钟，不花钱、不用安装。任务是：从零开始打一场战斗，再做一道菜回血。过程中录个屏，最后填一个 9 项的打分表就行。主要想找真实卡点，不用客气，直接骂。

## 2. 发给测试者前的检查

- 链接必须是测试者能直接打开的地址；当前线上仍是旧版，本地改动未 push，所以不要把本地路径直接发给测试者。
- 如果只在本机测试，请开本地 HTTP 服务；如果发给别人，先确认可访问链接，或等 push 确认后再用公开 URL。
- 提醒测试者用无痕窗口或清空存档，避免旧存档影响“从零开始”任务。

## 3. 统一测试任务

1. 打开游戏链接，无痕窗口或清空存档。
2. 开始冒险 → 跳过开场 → 走完 5 步教学。
3. 探索第一层，遇到战斗后打赢一场。
4. 收集食材，去烹饪食堂做一道菜并食用回血。
5. 全程录屏；浏览器控制台如果有红色报错，记录时间和步骤。

建议时长：5-10 分钟。超时不强求通关。

## 4. 反馈表

评分口径：5 = 完全清楚 / 非常好 / 没遇到问题 / 愿意主动再玩；1 = 严重卡住 / 很差 / 问题很多 / 完全不想再玩。

| 维度 | 问题 | 1-5 | 证据字段 |
| --- | --- | --- | --- |
| 新手引导 | 从打开页面到第一次进迷宫，是否清楚每一步？最有/最没用的是哪一步？ | 1-5 | 录屏时间、卡住时长 |
| 目标感 | 当时知道为什么要探索、战斗、烹饪吗？主线任务有没有让你想继续？ | 1-5 | 复述目标、原话 |
| 战斗 | 攻击/技能/逃跑/切换队员/切换目标是否理解？有没有按错或看不懂？ | 1-5 | 录屏片段、操作次数 |
| 烹饪 | 能独立完成食材→烹饪→食用→回血吗？菜谱解锁和评级清楚吗？ | 1-5 | 是否求助、是否成功 |
| 对话 | 台词、魔物描述、事件文本是加分还是干扰？ | 1-5 | 引用一句台词 |
| Bug | 是否遇到按钮无响应、报错、卡死、存档丢失或读档不一致？ | 1-5 | 时间点、复现步骤 |
| 卡点 | 哪一步最卡？卡了多久？ | 1-5 | 卡住时长、尝试次数 |
| 时长 | 实际玩了几分钟？合适吗？ | 1-5 | 开始/结束时间 |
| 再玩 | 如果这是独立小游戏，还会再玩吗？为什么？ | 1-5 | 原话 |

## 5. 录屏要求

- 开启浏览器控制台，从打开页面录到吃完料理。
- 文件命名建议：`player_01_日期_设备_时长.mp4`。
- 如果文件太大，只保留三段：新手引导、战斗胜利、烹饪回血，每段不超过 3 分钟。

## 6. 回填格式

每位测试者保存一行：

`player_id, date, device, viewport, minutes, score_guide, score_goal, score_battle, score_cook, score_text, score_bug, score_blocker, score_time, score_replay, quote, best_moment, worst_moment, console_errors, recording_file`

回填位置：`05_dungeon_meshi_game/试玩反馈与录屏验收.md`

- 汇总 5 行到 `试玩反馈与录屏验收.md`，并把典型原话、卡点、Bug 归入问题清单。
- 修复后重跑 `verify_game.cjs`，再写进 CHECKPOINT。
