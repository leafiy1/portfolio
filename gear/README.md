# GearPick · FPS 外设智能推荐（外设推荐工具）

> 透明规则推荐，拒绝算法黑盒。三条信源交叉验证，每个推荐逐条可溯源。
> 维护人：陈昊｜数据版本：v4.3 ｜更新日期：2026-08-17

---

## 1. 项目简介

GearPick 是一个面向 FPS 玩家的外设推荐工具（鼠标 / 键盘 / 鼠标垫 / 耳机）。
它不采用"算法黑盒"式的打分推荐，而是采用**透明规则推荐**：

1. **先硬过滤**：按用户的预算、手型、握法、配列、连接方式等硬条件筛掉不合格产品；
2. **再偏好加权**：对极致轻量、人体工学、性价比、长续航、高回报率等软偏好加分；
3. **最后信源加分**：按"职业选手数据 / UP主评测 / 社区口碑"的信源覆盖与职业背书加分排序；
4. **每个结果都可展开"为什么推荐它"**：得分构成、推荐理由、注意事项、信源链接全部公开。

本仓库配套文档：

| 文件 | 说明 |
| --- | --- |
| `index.html` | 工具本体（数据以内嵌快照方式内置，双击即可用） |
| `products.json` | 产品库（234 款）的**权威数据源** |
| `CASE_STUDY.md` | 项目案例复盘（背景 → 角色 → 核心决策 → 结果 → 复盘） |
| `tools/enrich_products.py` | 数据厚化脚本（v1→v2 派生字段，可复跑） |
| `tools/embed_products.js` | 数据同步脚本（products.json → index.html 内嵌快照） |

## 2. 本地运行

**方式 A（最简单）**：直接双击打开 `index.html`。产品数据已内嵌，无需服务器、无需联网。

**方式 B（本地服务器）**：

```bash
# 在 gear 目录下
python -m http.server 8000
# 浏览器打开 http://localhost:8000/
```

**更新数据后的同步步骤**（重要）：

```bash
# 1. 编辑 products.json（权威数据源）
# 2. 重新生成内嵌快照，保持 index.html 与 products.json 一致
node tools/embed_products.js
```

> 说明：浏览器出于安全限制不允许 `file://` 页面通过 `fetch` 读取本地 JSON，
> 因此产品库以内嵌快照形式写入 `index.html`；`products.json` 始终是唯一权威源，
> 任何结构变更都必须重跑 `embed_products.js` 同步。

## 3. 数据来源与口径

### 3.1 三重信源定义

| 信源类型 | 定义 | 代表入口 | 作用 |
| --- | --- | --- | --- |
| `pro` 职业数据 | 职业选手公开的比赛/直播配置 | [fireopen.cn](https://www.fireopen.cn/) | 权威背书，验证"职业选手真的在用" |
| `bilibili` UP主评测 | 外设区 UP 主的横评 / 618 推荐视频 | B站搜索（链接内嵌） | 时效性强，覆盖价格与购买建议 |
| `community` 社区口碑 | 玩家社区的长尾使用反馈 | NGA 硬件外设区 / Reddit 对应分版 | 校验长期使用后的真实体验 |

**交叉验证口径**：
- 三类信源都覆盖 → `三重信源交叉验证`；
- 两类 → `双信源交叉验证`；
- 仅一类 → `单信源（待补强）`，工具会在解释区明确提示"购买前建议再参考社区反馈"。

**当前覆盖情况（如实展示，v4.3 扩库+价格核实后）**：234 款中，三重信源 10 款、双信源 167 款、单信源 57 款。
v4.0 新增 168 款近两年新品，全部带可核实信源；v4.1 完成 42 款价格核实，v4.3 再补 11 款公开参考价，当前仅 kb-029 留空并标注「待核实」。
其余单信源多为国产新型号（社区口碑信源尚未系统采集）。这是已知局限，也是下一步迭代项，
不是隐瞒的"漏洞"——工具会把每一款的信源覆盖情况如实呈现给用户。

### 3.2 价格口径

- **全部为参考价**，来自 618 横评视频、官方报价页与电商行情，随渠道与活动浮动；
- 部分型号带 `price_note` 字段标注口径（如"大号 ¥49，另有小号 ¥39"、"官方参考价 ¥399"）；
- 已核实价格同时记录 `price_verified_at` 与 `price_sources`，来源可展开复核；
- 无法核实的价格不估算，前端显示「价格待核实」，预算筛选时不会把缺价型号当成任意档位推荐；
- 页面与导出文件均明确提示"以电商实时价格为准"。

### 3.3 信源链接约定

- 优先使用**稳定的官网首页 / 参数页 / 评测原文入口**（如 `fireopen.cn`、品牌官网、B站/什么值得买/Reddit 搜索），保证链接长期可点；
- 具体评测视频的**深链以【待补充】标注**，由候选人核实后替换为精确链接；
- 新增产品必须带 `sources` 字段，否则不允许入库（见数据治理红线）。

### 3.4 数据治理红线（写进流程的规则）

1. **严禁虚构真实产品的规格参数**：只能收录可核实的参数，无法核实的字段留空（前端显示「—」）；
2. **新增型号必须带 `sources`**：至少一个公开可信信源可核实，否则不新增；
3. **结构变更必须同步前端**：改 `products.json` 后必须跑 `embed_products.js`。

## 5. 推荐与排序逻辑（规则公开，非黑盒）

```
score = 需求匹配分 + 信源分 + 偏好加分

需求匹配分 = 命中的硬条件数 × 10      （预算/手型/握法/配列/连接等）
信源分 = min(信源类型数 × 8, 24)  + 有职业选手背书 +10  + 推荐点评厚度(≤6)
偏好加分   = 命中的软偏好数 × 10       （轻量/工学/性价比/续航/高回报率/常玩游戏/用途）
```

- 排序：得分降序 → 同分按价格升序（缺价条目排后）→ 再按收录顺序（榜单优先级）；
- **空结果兜底**：严格过滤无结果时，按品类优先级自动放宽条件（如先放宽握法、再放宽手型、最后放宽预算），并在结果顶部明确提示"已自动放宽条件：xxx"，绝不让用户面对空白；
- 页面每个结果卡都展示得分条，解释区展示三项得分构成与计分规则说明。

## 6. 交互与状态设计（v3.0 视觉提质后）

- **完整链路**：选品类 → 填需求 → 开始推荐 → 展开"为什么推荐它" → 加入对比 → 复制/导出；
- **首屏 Hero**：产品主张 + 真实数据可视化（收录数、三重/双/单信源结构、三类信源覆盖条形图，全部由 products.json 实时计算，非装饰）；
- **可解释区**：得分构成（含迷你条形图）/ 推荐理由 / 注意事项 / 信源溯源（覆盖度圆点 + 验证状态徽章 + 逐条链接）/ 计分规则脚注；
- **对比**：最多选 3 款，弹出逐字段对比表，首列「最佳推荐」高亮；
- **导出**：一键复制 Markdown 摘要，或下载 `.md` 文件（含理由与信源）；
- **状态兜底**：空态（"档案室已就绪" + 一键默认推荐）、加载态、错误态（重试）、空结果（自动放宽提示）；
- **选购指南**：页面底部附四品类选购指南 + 5 条 FAQ（可折叠，克制不抢主流程）；
- **响应式**：桌面三列表单 / 移动端单列，Hero 统计 4 列 → 2 列，对比表横向滚动。
