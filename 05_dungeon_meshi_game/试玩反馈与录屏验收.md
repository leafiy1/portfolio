## 1. 5 人试玩反馈表

评分口径：5 = 完全清楚 / 非常好 / 没遇到问题 / 愿意主动再玩；1 = 严重卡住 / 很差 / 问题很多 / 完全不想再玩。

| 维度 | 问题 | 1-5 | 证据字段 |
| --- | --- | --- | --- |
| 新手引导 | 从打开页面到第一次进迷宫，你是否清楚每一步？教学最有用和最没用的是哪一步？ | 1-5 | 录屏起止时间、卡住时长、截图 |
| 目标感 | 你当时知道为什么要探索、战斗、烹饪吗？主线任务有没有让你想继续？ | 1-5 | 复述目标、是否看任务栏、原话 |
| 战斗 | 你理解攻击/技能/逃跑/切换队员/切换目标吗？有没有按错、看不懂或觉得重复？ | 1-5 | 录屏片段、操作次数、是否有死局 |
| 烹饪 | 你能独立完成「获得食材 → 烹饪 → 食用 → 回血」吗？菜谱解锁和评级清楚吗？ | 1-5 | 是否求助、是否成功、截图 |
| 对话 | 角色台词、魔物描述、事件文本是加分还是干扰？有没有过长、重复或出戏？ | 1-5 | 引用一句台词、是否跳过文本 |
| Bug | 有没有遇到按钮无响应、报错、卡死、存档丢失或读档不一致？ | 1-5 | 时间点、控制台、复现步骤 |
| 卡点 | 哪一步最卡？是引导、解锁、打不过、没食材、找不到入口，还是不知道下一步？ | 1-5 | 卡住时长、反复尝试次数 |
| 时长 | 你实际玩了几分钟？这个时长合适吗？ | 1-5 | 开始与结束时间 |
| 再玩 | 如果这是独立小游戏，你还会再玩吗？为什么？ | 1-5 | 原话、是否主动继续玩 |

每位测试者保存一份汇总行：

`player_id, date, device, viewport, minutes, score_guide, score_goal, score_battle, score_cook, score_text, score_bug, score_blocker, score_time, score_replay, quote, best_moment, worst_moment, console_errors, recording_file`

## 2. 完整对战录屏/验收清单

统一测试任务：从零开始，打一场战斗胜利，并完成一次烹饪回血，尽量控制在 5-10 分钟。

- [ ] 准备：无痕窗口或清空存档，录制全程，开启浏览器控制台。
- [ ] 标题页：版本 v2.5.0；无存档时只显示「开始冒险」。
- [ ] 开场：开始冒险 → 开场动画 → 跳过 → 5 步教学 → 进入主界面。
- [ ] 主界面：队伍、金币、图鉴、食材、主线任务和标签页正常；图鉴分母为 70，食材分母为 36。
- [ ] 探索：点击「探索第一层」，遇到宝箱/事件/陷阱记录弹窗；若未遇战斗，继续探索直到触发。
- [ ] 战斗开始：魔物名、属性、HP、攻击、战利品、技能区和队员选择区可见。
- [ ] 操作链路：攻击一次，确认伤害、战斗日志、敌人 HP 下降、敌人反击；使用一次技能；切换队员后继续攻击。
- [ ] 胜利结算：确认金币、食材、经验、成就/主线更新，不重复发放；无 JS 错误。
- [ ] 烹饪回血：切到烹饪食堂，烹饪一道可做菜谱，记录评级，食用后确认 HP/饱腹上升。
- [ ] 存档读档：保存后刷新，从标题页继续，确认关键状态一致。
- [ ] 移动端：用 375×667 与 414×896 各跑一遍，检查无横向滚动、按钮可点、文字不重叠、战斗区不挤爆。
- [ ] 通过标准：桌面和移动端均无控制台错误；全部按钮有响应；无软锁；存档读档一致。

## 3. 自动化回归建议

- 静态数据不变量：6 层、31 魔物、36 食材、28 常规菜谱、11 隐藏菜谱、42 事件、31 成就；图鉴分母断言 70。
- 新游戏链路：清空 `localStorage` 后调用 `newGame()`，断言主界面、教学弹窗、跳过可用。
- 战斗链路：触发 `startBattle('slime')` 循环攻击到胜利，断言奖励和状态；再测 `gluttonking`，确认多目标和团灭不软锁。
- 烹饪链路：注入食材后调用烹饪/食用，断言评级、血量、饱腹和图鉴变化。
- 存档链路：保存、刷新、读档，比较金币、任务、层进度和队伍状态。
- 响应式：桌面和移动端检查 `scrollWidth <= viewport`，375px 下截图。
- 性能：记录首屏加载时间，回填 CASE_STUDY 的加载时长空项。
